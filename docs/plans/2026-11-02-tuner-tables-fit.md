# Tuner tables without sideways scrolling: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resize the Tuner page's cards and tables so a run's results fit the width of the page. Nobody should
have to scroll the Candidates table sideways to see the Draft, VRAM or Score columns.

**Architecture:** CSS and rendering changes only, no backend. Give the Tuner page more width, let the long
columns wrap at sensible places (between flags, never inside `-ctk q8_0`), stack the result reason under its
badge instead of beside it, fold the Confirmed column into Score, and leave out columns a run has no data for.
Two small pure helpers decide where labels may wrap and which columns to show, and `node --test` tests them.

**Tech stack:** React 18 + `htm` + the Ember `Table` component (`web/vendor/ember.js:664`), plain CSS in
`web/css/app.css`.

**Spec:** the user's request: "I want the boxes resized so that the data from the tuning runs doesn't require
scrolling side to side."

## The problem, measured

`docs/screenshots/tuner-candidates.png` shows it. In a 1,280 px wide card, the Candidates table's last four
columns (Draft, VRAM free, Confirmed, Score) are cut off, and you have to scroll to see them. The causes, in
`web/js/pages/tuner.js:300-319`:

1. **Candidate** is rendered inside `<span className="nowrap">` (line 303), so a label like
   `-ctk q8_0 -ctv q8_0 · -fa on · -ub 1024 -b 2048 · MTP 4` (~60 monospace characters) can never wrap.
2. **Result** puts the badge and the error text side by side in a `nowrap` row, with the text cut to 220 px
   (lines 305 and 311). The full reason is only in a tooltip.
3. **Eleven columns**, and some are often empty: Draft (`–` for every run without speculative decoding),
   VRAM free (`–` on a box without GPU readings), Confirmed (empty for "one flag at a time" runs).
4. Ember's table headers are `white-space: nowrap` (`web/css/ember.css:292`), so "Decode deep" and
   "Prefill deep" are as wide as their header text.
5. The page is capped at `--content-max: 1280px` (`web/css/app.css:22`, `web/css/tokens.css:149`) even on a wide
   monitor, while the side navigation takes 240 px and the page padding takes 80 px.

## What the user sees when this is done

- At window widths of **1280, 1440 and 1920 px**, no table, code block or card on the Tuner page has a
  horizontal scrollbar, for a finished grid run with speculative decoding (MTP and a DSpark file), pruned rows,
  skipped rows and confirmed finalists.
- A long candidate label wraps onto a second line *between* flags (`-ub 1024 -b 2048` stays together), with the
  `·` separators kept.
- A Skipped/Pruned/Too big badge has its full reason under it, wrapping, never cut off with "…".
- The Score column shows the score and, for finalists, `confirmed +3.1%` under it. There is no separate
  Confirmed column.
- Draft and VRAM free only appear when at least one trial in the run has a value for them.
- On a wide monitor the Tuner page uses up to 1,600 px instead of 1,280 px. Other pages don't change.
- Below 1,024 px (tablets, phones), the Candidates table may still scroll sideways. That's out of scope here.

## Global constraints

- Don't edit `web/vendor/ember.js` or `web/css/ember.css` (vendored design system) or `web/css/tokens.css`
  (generated by `scripts/gen_tokens_css.py`). Override in `web/css/app.css`, scoped to classes this plan adds.
- Other pages must look exactly as before. Scope every new rule to `.page--wide` or `.tune-table`.
- Sorting by Decode, Decode deep, Prefill deep and Score keeps working.

## Review focus

1. **A quick-mode speculative label** has no ` · ` separators at all
   (`--spec-type draft-dspark -md dspark-MiniCPM-V-4_7-35B-A3B-F16.gguf --spec-draft-n-max 3`). It must still
   wrap, between its flags (`labelChunks` test).
2. **A negative value** like `-t -1` must not be split from its flag (`labelChunks` test).
3. **A run where nothing succeeded** (every trial failed): the optional columns are hidden and the table still
   renders (`columnsWithData` test with no ok trials).
4. **Rows from old runs** stored before this change render the same way (no new fields are needed, so this
   holds by construction. Check one old run in Past runs by hand).
5. **The running card and the queue card** (if those plans have been merged) are on the same page. The width
   check in Task 2 covers every table and `<pre>` on the page, not just Candidates.

### Task 1: Decide where labels wrap and which columns to show

**Files:**
- Create: `web/js/tunetable.js`
- Test: `web/test/tunetable.test.mjs`

**Interfaces (Produces):**

```js
// A candidate label as parts (split on ' · ') of chunks (split before each flag), so the page can let the
// browser wrap only between chunks: '-ctk q8_0 -ctv q8_0 · MTP 4' -> [['-ctk q8_0', '-ctv q8_0'], ['MTP 4']].
export function labelChunks(label)        // string | undefined -> string[][]
// Which optional columns this run has data for.
export function columnsWithData(trials)   // -> { draft: boolean, vram: boolean }
```

Like `web/js/tuneplan.js`, this file **imports nothing**, so Node can test it without a browser.

- [ ] **Step 1: Write the failing tests** in `web/test/tunetable.test.mjs`

```js
import test from 'node:test';
import assert from 'node:assert/strict';
import { labelChunks, columnsWithData } from '../js/tunetable.js';

test('labelChunks keeps each flag with its value and the parts apart', () => {
  assert.deepEqual(labelChunks('-ctk q8_0 -ctv q8_0 · -fa on · -ub 512 -b 2048 · MTP 4'),
    [['-ctk q8_0', '-ctv q8_0'], ['-fa on'], ['-ub 512', '-b 2048'], ['MTP 4']]);
  assert.deepEqual(labelChunks('-c 65536 · -ngl auto · -ctk f16 -ctv f16 · no spec'),
    [['-c 65536'], ['-ngl auto'], ['-ctk f16', '-ctv f16'], ['no spec']]);
});

test('labelChunks splits a label without separators before each flag', () => {
  assert.deepEqual(labelChunks('--spec-type draft-dspark -md dspark-Fake.gguf --spec-draft-n-max 3'),
    [['--spec-type draft-dspark', '-md dspark-Fake.gguf', '--spec-draft-n-max 3']]);
});

test('labelChunks does not split a negative value from its flag', () => {
  assert.deepEqual(labelChunks('-t -1 -tb 24 · no spec'), [['-t -1', '-tb 24'], ['no spec']]);
});

test('labelChunks of nothing is nothing', () => {
  assert.deepEqual(labelChunks(''), []);
  assert.deepEqual(labelChunks(undefined), []);
});

test('columnsWithData shows Draft and VRAM only when a trial has them', () => {
  assert.deepEqual(columnsWithData([{ ok: true, draft: null, vram_free_mib: null }]), { draft: false, vram: false });
  assert.deepEqual(columnsWithData([{ ok: true, draft: 0.71 }, { ok: false }]), { draft: true, vram: false });
  assert.deepEqual(columnsWithData([{ ok: false, probe: true, vram_free_mib: 812 }]), { draft: false, vram: true });
  assert.deepEqual(columnsWithData([]), { draft: false, vram: false });
});
```

Note the VRAM case: probes and too-big trials report free VRAM too (the table shows it for them), so `vram`
looks at every trial, while `draft` only counts trials that succeeded (`ok`), because that's when the table shows it.

- [ ] **Step 2: Run to see them fail**: `node --test web/test/` → `Cannot find module '…/tunetable.js'`.

- [ ] **Step 3: Implement.** `labelChunks`: return `[]` for a falsy label, else split on `' · '`, then split
  each part with `/ (?=--?[A-Za-z])/` (a space followed by `-` or `--` and a letter: the start of a flag. `-1` has
  no letter after its dash, so it stays with `-t`). `columnsWithData`: `draft` is `trials.some((t) => t.ok && t.draft != null)`,
  `vram` is `trials.some((t) => Number.isFinite(t.vram_free_mib))`.

- [ ] **Step 4: Run to see them pass**: `node --test web/test/`.

- [ ] **Step 5: Commit**: `git commit -m "Tuner table: helpers for label wrapping and optional columns"`

### Task 2: Use them, and resize the page and table

**Files:**
- Modify: `web/js/pages/tuner.js:70` (page class), `:290-345` (`TuneResult`'s `columns` and its `E.Table`)
- Modify: `web/css/app.css` (new block after the stage tracker block, ~line 283)

**Interfaces:**
- Consumes: `labelChunks`, `columnsWithData` from Task 1.
- Produces: `function CandidateLabel({ label })` in `tuner.js`: renders `labelChunks(label)` as
  `<span className="flags">`, each chunk in `<span className="flags__chunk">`, chunks within a part separated by
  a space, parts separated by `<span className="flags__sep"> · </span>`.

- [ ] **Step 1: Implement**

1. `TunerPage` (line 70): `className="page page--wide"`.
2. In `TuneResult`'s `columns` (lines 300-319):
   - `stage`: render it as `` html`<span className="nowrap">${t.stage}</span>` `` so "KV cache" stays on one line.
   - `label`: render `` html`<${CandidateLabel} label=${t.label} />` `` instead of the `nowrap` span.
   - `result`: wrap each case in `<div className="cell-main">` with the badge first and the reason (if any)
     under it as `<span className="cell-sub text-caption result-why">${t.error}</span>`. Remove the `row`/`nowrap`
     wrappers, the `truncate` class and `maxWidth: 220`. Keep `title=${t.error}` if you like, but the text must
     be fully visible without it.
   - Delete the `final` (Confirmed) column. In `score`'s `render`, when `t.final_score != null`, render
     `<span className="num-stack">` with the score line first and a `text-caption subtle` line
     `` `confirmed ${…}` `` under it, using the same `+x.x%` formula the Confirmed column used.
   - Filter the columns: `const show = columnsWithData(trials);` and drop `draft` when `!show.draft` and `vram`
     when `!show.vram`.
   - Give the Candidates `E.Table` `className="tune-table"`. If the [tuning queue](2026-11-02-tuning-queue.md)
     has been merged, give the Queue card's table the same class.
3. `web/css/app.css`, a new block:

   ```css
   /* ---------------------------------------------------------------- tuner tables */
   .page--wide { max-width: 1600px; }
   .tune-table th { white-space: normal; height: auto; padding-block: var(--space-2); line-height: 1.25; }
   .tune-table td { padding-block: var(--space-2); }
   .flags__chunk { display: inline-block; max-width: 100%; overflow-wrap: anywhere; }
   .flags__sep { color: var(--ink-subtle); }
   .result-why { display: block; max-width: 18rem; white-space: normal; overflow-wrap: anywhere; }
   .num-stack { display: inline-flex; flex-direction: column; align-items: flex-end; }
   ```

   Why `inline-block` chunks: the browser only breaks a line between inline-blocks, so `-ub 1024 -b 2048` never
   splits in the middle of `-ub 1024`. `max-width: 100%` plus `overflow-wrap: anywhere` is the safety net for a
   single chunk wider than the column (a very long draft file name), which then wraps inside itself instead of
   widening the table.

- [ ] **Step 2: Verify the widths**


Expected: `[]`. If something is listed, the class names tell you which element overflows. Inspect it and find
the column with the widest content.

Also check by eye: labels wrap between flags, reasons are fully readable, sorting by Score still works, and
